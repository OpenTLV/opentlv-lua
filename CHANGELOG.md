# Changelog

All notable changes to this project will be documented in this file.

## [Unreleased]

### Added

- Add separately approved LuaRocks publication. The release gate rebuilds the release rockspec and source rock from the release commit, requires the digests recorded by every static-Core Full configuration, and attaches both files to the GitHub Release, covered by `SHA256SUMS` and attestations, as immutable release assets. The manual `luarocks-release.yml` workflow publishes the tag of an existing GitHub Release. Without the credential, it verifies the published release, tag commit, asset digests and attestations, the Full evidence and successful release jobs of the same attempt, and that the rock rebuilds byte-identically from the tag. A second job then runs only after approval in the `luarocks` environment, which alone holds `LUAROCKS_API_KEY`. It repeats the verification and uploads exactly the attested files through the luarocks.org upload API, without `--force`. The key is kept out of child processes, arguments, output and error messages. An existing version is never replaced: different remote files fail the run, identical ones succeed, and an interrupted upload only adds the missing source rock. The upload fails if another account owns the name or the module is not added to the root manifest. The run reads both files back from the account manifest and records a receipt. The release guide documents the environment setup, procedure and recovery. (#45)

- Validate the release rock on every static-Core Full configuration: Linux, Windows and macOS with Lua 5.1–5.4 and Linux LuaJIT. `scripts/check_release_rock.py` builds the `.src.rock` of the tested commit the way `luarocks pack` would, byte-identical on every platform, then unpacks and makes it into a fresh tree without a Core override. It checks that the fetched Core is the pin, compares the installed rockspec, facade, `LICENSE`, `LICENSE-Core` and release metadata with the commit and the verified Core, loads the tree's native module from its search paths alone, and runs the twelve relocated module scripts, the Query corpus and the quick start. Release runs require the candidate tag to select the tested commit; other Full runs use the fixture tag `v0.0.0`. The aggregate and release gates require this evidence from all 13 configurations, with identical rock and rockspec digests and, for a release, the requested tag. The rock now installs Core's license as `doc/LICENSE-Core`, from the Core source or an installed package. A release build no longer searches for installed Core packages, so an unrelated installed OpenTLV cannot replace the pin. The versioning guide documents the rock contents, Core selection, build requirements and supported targets. (#44)

- Prepare the `opentlv` LuaRocks rock: `scripts/rockspec.py vMAJOR.MINOR.PATCH` generates `opentlv-MAJOR.MINOR.PATCH-N.rockspec` from the `opentlv-scm-1.rockspec` of that release tag, changing only the version, the source tag and the declared release tag, so the single rock keeps the native `opentlv._core` module and pure-Lua facade with their build and install commands. LuaRocks deletes `.git` from the tag it clones, so a release rock reported `scm+unknown`; the rockspec now passes `OPENTLV_LUA_RELEASE_TAG`, which identifies a source tree without Git and must match the tag of a Git checkout, and the development rockspec passes it empty. Tags `v0.1.0` and `v0.2.0` lack it and are rejected. The versioning guide records the verified LuaRocks name and account and the release rockspec procedure; upload remains separate and requires approval. (#43)

## [v0.2.0] - 2026-10-27

### Changed

- Prepare the independently versioned Lua v0.2.0 release against Core v0.8.0: pin both dependency selectors to `345c77acb29266036df5f27d04ce315bb61853cc`, select the published Core release for authenticated binary/source consumption, recheck generic API completeness and document the remaining release gates. Preserve the original migration provenance. (#40)
- Normalize Lua licensing and community policies to the Workspace reference: `REUSE.toml` and `LICENSES/MIT.txt` cover every file, listing documentation, JSON data and the byte-preserved migration records (the initial source inventory and the historical README) by exact path, and the rockspec, clang-format, clang-tidy, pre-commit and Git configuration and `requirements-dev.txt` gain SPDX headers. The pre-commit hooks of the source quality job run `reuse lint` with REUSE 6.2.0, and licensing regression tests reject glob or stale annotations, a changed historical README, a license text differing from `LICENSE`, a rockspec without `MIT` and OpenTLV as a copyright holder. The README and the development guide state Marek Cingel's copyright, contributor ownership, the license notices of module archives, the rock and binaries that statically link Core, and the shared `OpenTLV/.github` contribution, conduct, security and support policies. (#38)
- Report the independent Lua binding version through `version()` and `_VERSION`, using the same generated value as package/release metadata, with Lua checks for build and installed package consistency. Core identity remains in build/release provenance only. (#18)
- Require all stable Core features supported by Lua in every official build, remove Core feature selection, reject incomplete Core packages, and align component checks and documentation with the single full-featured configuration. (#16)

### Fixed

- Recover timing telemetry from the final `Complete job` step when GitHub leaves a job marked `in_progress` despite all steps being complete; verify the run/attempt and step timestamps, label the fallback source and preserve the API's unknown conclusion without changing quality or release gates. (#40)
- Allow delayed GitHub Actions job timing metadata to arrive over 18 attempts at 10-second intervals, retaining exact-attempt collection and rejection of incomplete reports; include pending job details in retry and failure diagnostics. (#40)
- Correct the `LICENSE` copyright holder from the OpenTLV organization, inherited from the GitHub template, to Marek Cingel, matching the source headers and the Core license; packages built from this revision carry the corrected `LICENSE-Lua`. (#23)
- Distinguish migration-era Core-aligned documentation from current independently versioned Lua manuals, while preserving source provenance and historical validation. (#21)
- Make shared Core DLLs discoverable by Windows Lua tests and run the LuaRocks package manager under PUC Lua for LuaJIT to avoid oversized-manifest failures. (#13)

### Added

- Add the Workspace `.markdownlint.json` configuration and explicit MIT licensing in `REUSE.toml` to align Markdown lint settings across repositories. (#40)
- Complete and gate the generic Core API: `opentlv.definition_registry(definitions)` snapshots `{tag, name}` entries, and `registry:find(tag)` returns an owned copy of the first entry with an equal Tag and its index through `tlv_definition_find()`, or `nil`; `registry:definitions()` returns the entries in order. Diagnostic tables with a tracked path gain `path_text`, Core's `tlv_diagnostic_path_string()` formatting of the enclosing Tags, such as `"30 > A5"`, ending in `" > ..."` when truncated. The `audit.lua` example names a Schema finding through a registry and prints its path. `tlv_location_translate` joins the API coverage ignore list with its reason: Lua has no caller-owned destinations or sub-buffer origins, so Core's coordinates are reported unchanged. `cmake/api-coverage.json` lists `core` as `complete`, so `Core API coverage` fails when a core symbol is neither referenced nor ignored or an ignore pattern matches nothing, after writing and uploading its report, and is now a `Lua quality gate` prerequisite instead of an informational job. The Core API coverage record (`docs/api-coverage.md`) is the reviewed baseline for Core pin updates: every core header with its public Lua API and binding tests, the exclusions, the limitations and the update procedure. Core coverage of Core `d87dcf96b270` is 204/204 (100.0 %) with 93 ignored. (#31)
- Complete generic codec and wire generation APIs: `opentlv.codecs.schema_number{rule = ..., encoding, width, digits}` limits a numeric codec by a length rule through `tlv_schema_number_codec()`, checking Value lengths before decoding and encoding in the shortest permitted width, and also works as a Query provider codec. `opentlv.structure_codec(config)` maps one complete sequence to one Lua value through `tlv_structure_decode()` and `tlv_structure_encode()`: C validates framing, nesting, limits and an optional Schema or checked Schema before the `decode` callback sees the sequence, and validates the string `encode` returns before handing it back, with Reader or Schema findings in `codec_detail` and output coordinates for encode failures. `opentlv.generator(config)` generates reproducible Writer-reconstructible cases through `tlv_generate()` from candidate identifiers with inclusive Value size intervals, element, depth, Value and case limits and a 64-bit seed; `generate(case_index)` returns one case, `workspace_size()` reports its scratch size through `tlv_generator_workspace_size()` and `opentlv.GENERATOR_VERSION` exposes the algorithm version. The new `generate.lua` example decodes generated records through a structure codec, and the API guide no longer lists the Document builder as unbound. The number, text, digits and Schema-number codec callbacks that Core's inline constructors install are in the API coverage ignore list with their reason; core coverage of Core `d87dcf96b270` is 202/205 (98.5 %). (#30)
- Complete Document, Query and Schema operations: `document:revision()` counts successful edits, `node:source_location()` reports retained original input coordinates, `document:find_child(tag, parent)` finds a direct child by tag and `document:visit(path, callback)` visits path matches as Nodes through `tlv_document_query_visit()`, which `document:query()` now also uses. Nodes are checked with Core's never-reused node identity, `tlv_document_retire_epoch()` and `tlv_document_node_identity()` instead of a binding-side handle list; an applied Query edit still invalidates every earlier Node. `tree_reader:document_builder(options)` copies the whole stream, the next subtree or the subtree of the item `next()` returned into a Document through the C Document builder, resumes after `NEED_MORE_DATA` and owns the cursor until it completes. `query:format()` and `tostring(query)` return the canonical path through `tlv_query_format()`, `query:visit()` visits complete input through `tlv_query_visit_buffer()`, and matcher `visit()` runs `tlv_query_visit()` and returns `visited, stopped`. Compiled Query programs with static names compile directly through `tlv_query_compile_scratch()` and `tlv_query_compile()`; `opentlv.query_plan_open()` and `program:plan_info()` open and inspect native plans without the Query frontend; `execution:reset()` resets in place through `tlv_query_exec_reset()`; `execution:visit()` visits Document results as Nodes through `tlv_document_query_program_visit()`; Document evaluation without a capacity sizes the Value snapshot with `tlv_document_query_value_size()`; providers accept Value codecs decoded by `tlv_query_codec_decode()`; and Query errors carry `cause` and `cause_name`. `schema:check()` checks a definition once through `tlv_schema_prepare()` and returns a checked Schema that validates through `tlv_schema_validate_checked()` and `tlv_schema_validate_all_checked()`, `validate(data, format, {first = true})` stops at the first failure through `tlv_schema_validate()`, Schema diagnostics carry their `cause`, `opentlv.length_schema()` finds and validates per-tag lengths, and `opentlv.value_constraint()` checks, validates and names decoded values. The new `audit.lua` example builds a subtree Document and validates it with a checked Schema and a value constraint. `tlv_query_parse()` and `tlv_schema_check()` are in the API coverage ignore list with their reasons; core coverage of Core `d87dcf96b270` is 198/213 (93.0 %). (#29)
- Stream through native Reader, Tree Reader and Writer sessions: `opentlv.reader(data, format, {final_input = false})` and the new `opentlv.tree_reader(data, format, options)` read incremental input, raising `NEED_MORE_DATA` until `set_input(data, discard, final_input)` supplies a window that keeps the undiscarded bytes, and report `consumed()`, absolute `offset()` and `at_end()`. `opentlv.tree_reader()` pulls preorder items with `depth` and `constructed`, balanced `begin`/`element`/`end` events through `next_event()`, skips subtrees with `skip_subtree()` (also after a failed descent) and applies frame, depth and element limits. `reader:visit()` and `tree_reader:visit()` resume the C Visitor on an existing cursor and reject reentry from the callback. `reader:next_source()` and `opentlv.read_source()` return an `opentlv.Source` with the original bytes and field layout; `source:preserve()` and `writer:preserve()` reproduce them through Core only while the element is unchanged. `opentlv.read()` reads one element, `writer:copy_encoded()` appends raw bytes and `opentlv.encoded_size()` measures an Element or a Value length. `tree_writer:write_event()` consumes the events a Tree Reader produces, and `opentlv.measure_tree()` and `opentlv.measure_events()` stage a whole tree in one call, reporting `required_data` and `required_scratch` when the workspace is too small. The new `stream.lua` example feeds chunked input through a Tree Reader into a Tree Writer. Wrappers that pass a NULL diagnostic to a bound `_diag` function, the Tag/Value and caller-storage write forms and `tlv_writer_copy_element()` are in the API coverage ignore list with their reasons; core coverage of Core `d87dcf96b270` is 166/215 (77.2 %). (#28)
- Compose custom Formats without C: `opentlv.formats.compose(config)` composes a fixed or variable identifier encoding (with an optional identifier policy) and a fixed, variable (with an optional length policy) or escaped length encoding, with TLV or LTV order, Value or Tag-and-Value length scope, tag-only identifiers and constructed-bit nesting, through Core's Fixed, tagged binary, Variable, escaped and generic field compositions. `opentlv.formats.packed(config)` composes a packed Tag/Length header with an owned canonical identifier table, and `opentlv.fields.read_packed()`/`write_packed()` extract and insert one bit field of a header integer. A composed Format snapshots its configuration into its own userdata and works with every Format entry point: Reader, Writer, Tree Writer, traversal, Query, compiled Query programs, Document and Schema validation. Every Format, including builtin and fixed ones, exposes `can_read()`, `can_write()`, `decode()`, `measure()` and `encode()`, failing with an error that carries the Format's operation, region, offset, required size and field ranges. The new `compose.lua` example uses one composed Format with Tree Writer, traversal, Query and Document. Callback implementations installed by bound descriptor initializers are in the API coverage ignore list with their reason; core coverage of Core `d87dcf96b270` is 147/235 (62.6 %). (#27)
- Report pinned Core API coverage in PR and Full CI as a non-blocking job: `TLV_API` functions and data referenced from the native module sources in `src`, in total and per header, for core and builtins separately; added and removed symbols when a pull request changes the Core pin; and a documented ignore list for primitives and diagnostic producers in `cmake/api-coverage.json`. The script is the Python and Rust repositories' standard-library report with `cmake/api-coverage.json` as its default configuration and a statement that symbol references do not prove functional parity; core coverage of Core `d87dcf96b270` is 118/254 (46.5 %). (#26)
- Notify Docs after successful Main CI when Lua documentation or examples change, using attempt-bound evidence and a separate dispatch workflow. (OpenTLV/opentlv-docs#42)
- Notify Docs after verified GitHub releases using exact release, commit and workflow-attempt evidence. (OpenTLV/opentlv-docs#42)
- Align Lua PR, Main, Full and Release gates with runtime and sanitizer coverage, verified Core dependencies, validated module packages and CI timing evidence. (#13)
